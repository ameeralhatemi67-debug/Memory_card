# Memory Card — Audit v2 (2026-10-21)

**Scope:** Every planning doc (`README`, `Roadmap`, `Status`, `progress`, `feature_checklist`, `docs/original/*`, `docs/other/Questions.md`, `docs/Audit/idea_Audit.md`), the engine research that the MVP actually depends on (RES-12 FSRS, RES-43 re-insertion, FES-46 gamification), all 8 reference PNGs, the 20 icons, the `text_Mockup/` lab and its screenshots, and the local toolchain.

---

## 1. Verdict

The **visual concept is excellent and distinctive** — monochrome papercraft, inverse-ink surfaces, stepped card fans, folder tabs, edge "ears". Nothing in the flashcard market looks like it. That is the asset worth protecting.

The **execution strategy is the problem.** The September audit said: stop researching, `flutter create`, build the core loop. The roadmap that followed did the opposite: Version 2.0 and 3.0 are *more* HTML-mockup work (100 % parity, a resizable phone frame, a sensory lab), and real code is pushed to Version 4.0. Two full versions of throwaway work stand between you and an app you can use.

Meanwhile **Flutter 3.41.9, the Android SDK, 5 emulators, Chrome and Visual Studio are already installed and healthy** on this machine. Nothing blocks building the real app today.

**Recommendation:** Collapse V2–V4 into one track: build the Flutter app directly against the reference PNGs. The Flutter app *is* the living design lab — it runs in Chrome (Flutter Web) for instant visual checks and on the Android emulator for touch/haptics. The resizable-frame requirement is covered by running the web build at any window size.

## 3. New findings (not in the September audit)

### F1 — CRITICAL · The core loop contradicts spaced repetition
`Questions.md` Q2.2: *"the card is technically never ending… swiped right go to the very back of the stack, swiped left go back N."* That is an **endless in-session loop**. FSRS is the opposite: a card you got right should **leave** and not come back for days. If both run at once, every right-swipe gets re-shown minutes later and FSRS logs it as a same-day review, which wrecks the intervals.

**Fix — "Due first, then free play":**
1. A session = cards **due today** + up to *N new* cards (daily cap, default 15).
2. Swipe **left** → FSRS grades `Again`, and the card is re-inserted N positions back (RES-43). It must be passed once before leaving the session.
3. Swipe **right** → FSRS grades `Good`; the card leaves the session and is scheduled.
4. When the due queue is empty → celebration → offer **"Keep going"**: a free-practice loop that is exactly your endless stack. It **does not write to FSRS**. You keep the "never-ending" feel and the science stays intact.

### F2 — HIGH · The FSRS-5 maths in RES-12 has errors
I checked RES-12 against the reference implementation (`py-fsrs`, FSRS-5):
- **Difficulty update is missing linear damping.** FSRS-5 uses `D' = D + ΔD·(10 − D)/9`; RES-12 §1.5 uses plain `D + ΔD`.
- **Mean reversion targets the wrong anchor.** FSRS-5 reverts toward `D₀(Easy)`, but RES-12 reverts toward `D₀(Good)` (5.28).
- **The post-lapse short-term cap is missing.** FSRS-5 takes `min(S'_f, S / e^(w17·w18))`.

These are small in code but they compound over months of reviews. **Don't port the 1,400-line paper by hand.** Use the open-spaced-repetition `fsrs` Dart package, or port `py-fsrs` with its test vectors as unit tests. Note that **FSRS-6** (21 params, trainable decay) is now current upstream. Isolate the scheduler behind an interface so upgrading later is a one-file change.

The rest of the research corpus probably has similar unverified details. Treat the 46 papers as inspiration, not as spec.

### F3 — HIGH · Font licensing
`BernardMTCondensed.ttf` was copied from the Windows/Office install and is **committed to git twice** (`fonts/`, `text_Mockup/fonts/`). Bernard MT Condensed is a commercial Monotype font. You can use it locally, but redistributing it inside an App Store or Play build, or in a public GitHub repo, requires a licence.
**Fix:** Keep it for private development. Before any public release, either buy an app-embedding licence or swap to an open-licensed condensed display serif. Keep the font behind one `AppFonts.display` token so the swap is a one-line change. Add the `.ttf` to `.gitignore` before the repo ever gets a public remote.

### F4 — HIGH · The mockup drifted away from the references
Measured from the PNGs, the real palette is tiny and strict:

| Token | Hex | Use |
|---|---|---|
| ink | `#333333` | dark surfaces / text |
| paper | `#F1F1F1` | light surfaces / canvas |
| gray ramp | `#464646 → #747474 → #9D9D9D → #D9D9D9` | folder depth, stack layers |
| red | `#D35F5F` (card) / `#FF8080` (delete) | accent, destructive |
| peach | `#FFC680` | archive, tab |
| blue | `#80AEFF` | move, tab |

The core rule the references follow is **inverse ink**: on a light canvas the surfaces are dark, and on a dark canvas the surfaces are light. The mockup instead uses a generic dark-SaaS look (near-black background, `#3B82F6`-style blue, Plus Jakarta Sans, emoji icons, glow pills). Its screens (see `docs/screenshots/`) are ordinary card lists, not the stepped-fan, tabbed-folder, edge-ear designs. The `progress.md` claim of "100 % typographic match" is an overclaim; only the headline font changed.

### F5 — MEDIUM · Decisions contradict each other
| Topic | Says A | Says B | Proposed resolution |
|---|---|---|---|
| Card creation | Q5.1: "later update" | Q11.2: full rich editor · Q12.3: "+" creates decks & cards | **MVP:** create decks + cards (plain text front/back + optional image). **Later:** rich formatting toolbar. |
| Folder empty state | Q9.2: "Create a deck — coming soon" | Q12.3: user can create decks | Drop "coming soon"; offer **Create deck** + **Browse shop**. |
| Audio | Q11.1: pre-made cards have audio | No audio files exist | Use the **platform TTS engine** (tiny, free, offline) for language decks. No recording UI in MVP. |
| Grades | Audit: 3 grades | Design: 2 swipe directions | Keep **binary** (left = Again, right = Good). FSRS handles pass/fail well, and it matches the design. |
| Import | Q5.2: no import in MVP | Audit: import is critical | **CSV/TSV paste-import in MVP** (about one day of work). Anki `.apkg` later. |

### F6 — MEDIUM · The membership card reads like a payment form
"Card Holder Name / XXXX XXXX XXXX XXXX" above "Sign in" looks like a credit-card capture form. Users get wary, and store reviewers may flag it.
**Fix (and it's more fun):** make the 16 digits **your stats**: `0142 · 0007 · 0091 · 2026` = cards mastered · streak · retention % · member-since year. The card is a trophy, not a form.

### F7 — MEDIUM · A 4-column shop doesn't fit a phone
At 390 px, 4 columns give tiles about 80 px wide, so titles in a condensed display font fit roughly 8 characters. The reference tiles are blank placeholders, so this was never tested with real content.
**Fix:** responsive masonry with 2 columns on phones, 3 on large phones/small tablets and 4 on tablets. Keep the staggered pill heights and the wide "featured" tile at the bottom.

### F8 — MEDIUM · Missing everyday essentials
- **Undo last swipe.** The swipe *is* the grade, so a misswipe corrupts the schedule. Show a 3-second "Undo" chip after each swipe. (The shake/two-finger version from RES-06 can come later.)
- **Where do streak and "due today" live?** Q10.1 wants a prominent streak, but no reference screen has a slot for it. Proposal: a small counter between the logo and the ⋮ menu in the header (`🔥 7 · 24 due`).
- **Tap alternatives to swiping.** The corner "ears" in `Cards_page.png` should be **tappable buttons** (Again / Good). That also covers accessibility and one-handed use.
- **Reverse cards** (back → front) per deck. This is essential for language learning.

### F9 — LOW · Documentation overhead
- There are 5 overlapping status docs (README, Roadmap, Status, progress, feature_checklist) with Obsidian front-matter. That is a lot of upkeep for a solo project.
- README's directory tree is stale (it still shows `research/`, `idea_Audit.md` etc. at the root).
- `Questions.md` starts with **283 blank lines**.
- The `[[Ideas/Future/…]]` links point to the old vault location.
- **Suggestion:** keep `README` (what and how to run), `Roadmap` (plan with checkboxes) and `progress` (dated log), and fold `Status` and `feature_checklist` into them.

## 5. Design improvements

1. **Turn the stepped fan into a progress meter.** The signature 5-step fan on each deck row can *show* mastery: each step = 20 % of cards mastered, and filled steps get darker. The deck's signature element then carries information instead of being decoration.
2. **Encode "due" on the folder tabs.** The 3 coloured spine tabs (blue/peach/red) are the 3 most recently used decks. Add a tiny count to a tab when that deck has cards due.
3. **One canvas rule, everywhere: inverse ink.** Encode it as a theme extension (`surface = invert(canvas)`), not per-screen colours.
4. **Card faces stay calm.** The study card is where reading happens: no tilt, no glow, generous type. Put the motion into the *transitions* (swipe, promote, ears), not the resting state.
5. **Reduced-motion mode** swaps rotation/scale for a slide + fade, and turns wiggles off. It also follows the OS setting.
6. **Celebration scales with the achievement:** a small tick for each card, a fanfare + wax-seal stamp only at the end of a session, and confetti only for streak milestones (7/30/100).

## 7. Proposed true MVP

**Screens (from the references):** Side drawer (folders) · Deck list · Study stack · Card editor (bottom sheet) · Shop (local curated catalogue) · Profile/membership card · Settings · Session-complete celebration.

**Engine:** FSRS (via interface) · session queue with RES-43 re-insertion · new-card daily cap · undo · free-practice mode · local persistence.

**Content:** 3 starter folders per Q9.1: *Languages* (Spanish, French, Arabic, English), *German* (A1 → B1 levelled decks) and *Coding* (Python, Dart, C++), each with ~30–50 cards. All of them are also in the shop catalogue so they can be reinstalled.

**Out of MVP:** accounts/OAuth (the login screen becomes the profile card), community publishing, AI, Anki import, gyro, glow shaders, sync, rich-text toolbar, image cropping.

## 8. Proposed architecture (Flutter)

```
app/                          ← flutter create (repo stays the project root)
  lib/
    main.dart
    core/      theme (tokens, inverse-ink), fonts, icons, motion, haptics, sound
    data/      models, repositories, persistence, starter-content loader
    engine/    scheduler (FSRS behind an interface), session queue, stats
    features/  drawer/ decks/ study/ editor/ shop/ profile/ settings/
  assets/      icons/ (cleaned svgs), fonts/, decks/*.json, sounds/
  test/        engine unit tests (FSRS vectors, queue rules), widget tests
```

- **State:** Riverpod. **Routing:** go_router. **SVG:** flutter_svg.
- **Persistence:** SQLite via Drift (works on Android/iOS/desktop, and on web via WASM). If Drift-on-web costs too much setup, fall back to a pure-Dart store for the web debug target only, behind the same repository interface.
- **Platforms:** Android + iOS for release; Web + Windows as debug targets for fast visual checks.
- Effects map to stock widgets: `Transform` (3D stack), `ShaderMask` (edge-sinking), `CustomPainter` (folder silhouettes, stepped fans, scalloped badges), `AnimationController` + springs (thresholds, overshoot).
